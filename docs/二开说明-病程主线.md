## 一、这次新增的功能

### 1. 病程主线（核心）

把同一个孩子的**多次就诊**串成一条线，比如「10 月咳嗽 → 11 月复诊 → 12 月痊愈」是一段病程。

- 可以新建病程，起个标题（如「反复咳嗽」），填起病日期。
- 在一份报告详情页点「加入病程」，就能把这份报告挂到某段病程上；也可以当场新建病程并挂进去。
- 一段病程里可以同时归集：**报告、诊断、用药、操作（手术/处置）、疫苗、指标、报告章节**。
- 归集是**精细**的：不是"整份报告搬进去"，而是能挑到具体某一条诊断、某一个药。
- 病程**不跨成员**：每个家庭成员各记各的，不会混在一起。

### 2. 病程时间轴

病程详情页是一条从上到下按时间排的线：

```
起病 → 症状 → 诊断 → 用药 → 操作 → 疫苗 → 转归
```

每条都能**就地回看报告原件**，也能从病程里**移除**（只解除关联，不删原始报告）。

### 3. 结构化症状

可以给病程补录症状（名称、程度、出现/消失时间），不是只能写一段文字。
症状会被疾病目录和检索一起用到。

### 4. 病因与转归（人工填写）

- **病因**：只能自己填。**AI 不会去猜病因**，这是特意设的红线——猜错了比空着更麻烦。
- **转归**：标记这段病程最后是好了、好转、还是没好，用来判断"这事结束了没有"。

### 5. 疾病目录（侧边栏新增页面）

侧边栏多了一个「疾病」入口，相当于一本**自动生成的病历索引**：

- 汇总这个成员历史上出现过的**全部诊断和全部症状**，去重后列出来。
- 分成**「诊断 / 症状」两个页签**，默认看诊断，页签上带条数。
- 采用**九宫格小方块**排列（电脑 3 列、手机 2 列），一眼扫完，不用拉长列表。
- 点任意一项，就能看到**历次就诊的清单**：什么时候、哪家医院、什么诊断、开了什么药。
- 诊断会做**别名合并**（比如"上呼吸道感染"和"急性上感"算同一条），避免一个病散成一堆。
- **支持隐藏和恢复**：不关心的条目可以藏起来，报告原文和病程里的记录都不受影响；
  报告被删掉或进了回收站，条目本来就不再出现。

### 6. 综合检索

疾病页顶部那个搜索框，一个关键词**同时匹配**：

> 症状 · 病因 · 病程标题 · 诊断 · 用药

直接给出符合条件的历次就诊，回答的就是那个最实际的问题：
**「什么时候、哪家医院、开了什么药」**。

### 7. 病程删除

病程列表和病程详情都能删，删前会二次确认。
采用**软删除**：报告、诊断、用药一个都不会少，只是不再归集到这段病程里。

### 8. 用药频次显示中文

保留处方上的原始写法，后面括号补中文含义：

| 原标签 | 显示为 |
| --- | --- |
| qd | qd（每日一次） |
| bid | bid（每日两次） |
| tid | tid（每日三次） |
| qid | qid（每日四次） |
| qn | qn（每晚一次） |
| q8h | q8h（每8小时一次） |
| prn | prn（必要时） |

疾病目录、病程时间轴、报告详情里的用药记录都已经生效。

### 9. 手动补录用药

报告里没抽到、或者医生口头嘱咐的药，可以直接补进病程：

- 时间轴上方点「**添加用药**」，填写药品名称、开始日期、单次剂量、服药频次、用法。
- 补录的用药与报告带出来的用药**并列展示**，并标一行「手动补录」以示区别。
- 可以单独删除，不影响报告里原有的内容。

### 10. 时间轴按类型配色

每种内容有自己的颜色，圆点和小标签同步上色，一眼分得开：

| 内容 | 颜色 |
| --- | --- |
| 报告 | 绿色 |
| **症状** | **橙色** |
| **用药** | **蓝色** |
| 诊断 / 操作 | 深绿 |
| 疫苗 / 已痊愈 | 亮绿 |
| 就诊卡片 | 绿色卡片（一次就诊一张） |

另外，**同一次就诊的内容会合并成一张卡片**（见下面第 11 节）：
一次就诊的报告、症状、诊断、用药不再各占一行、各重复一遍来源，而是收在一张卡片里。

### 11. 一次就诊 = 一张卡片

同一次就诊（同一份报告）的症状、诊断、用药、操作、疫苗收进**一张卡片**，不再每种各占一行、
每条都重复一遍「报告名 · 医院 · 日期」：

```
● 2026-10-09   急诊儿科门诊记录        郑州市中心医院 · 急诊儿科
    症状      咳嗽半天
    诊断      呼吸道感染
    医生开药  氨溴特罗口服溶液 · 5ml 口服 bid（每日两次）
              复方氨酚甲麻口服液 · 4.5ml 口服 tid（每日三次）
    提示：有诊断，但没抽到用药
    [查看报告]  [移除这次就诊]
```

- **缺口提示**：没识别到诊断、有诊断却没抽到用药、有条用药缺剂量 —— 卡片会主动说出来。
  AI 抽取本来就不保证全，让界面提醒你去核对原报告，比默默留空有用。
- 卡片里只有**你自己手动归集**的条目才带「移除」；报告展开出来的内容跟随报告，
  要改就改报告（这正是设计意图，不是缺按钮）。

### 12. 给医生看（就诊摘要）

点时间轴头部的**文档图标**，一键生成一段可直接复制/截图的文字：

```
【就诊摘要】张铭浩，1 岁 6 个月
起病 2026-10-09 ｜ 已持续 5 天 ｜ 病因 受凉
症状：咳嗽 昨天 08:00 存在；发热 38.5℃ 今天 15:30 好转
就诊：2026-10-09 郑州市中心医院 急诊儿科门诊记录；诊断 呼吸道感染；用药 氨溴特罗口服溶液 5ml 口服 bid（每日两次）
```

赶去医院时不用现想怎么说。没有剪贴板权限时（部分浏览器/非 HTTPS 环境），
可以直接**长按卡片里的文字**选中复制。

### 13. 发热小结

记过体温就会在病程信息下方出现一张小结卡：**最高值（含时间）、最近一次、发热天数、共记录几次**。
发烧时医生一定会问这几件事。

### 14. 快速记录（常用症状 + 一句话记录）

病程信息下方是「快速记录」：

- **常用症状快捷键**：发热 / 咳嗽 / 流鼻涕 / 鼻塞 / 腹泻 / 呕吐 / 皮疹，点一下就用当前时间开一条；
  点「发热」还会自动带出 ℃ 单位，你只管填数字。
- **一句话记录**：输入一句话回车，自动拆解并填进表单。除症状与体温外，**也能认用药**：

| 你打的 | 自动变成 |
| --- | --- |
| `5点半 37.5` | 今天 17:30 · 症状「体温」· 37.5℃ |
| `昨天下午体温3点 38.2度` | 昨天 15:00 · 症状「体温」· 38.2℃ |
| `下午吃氨溴特罗口服溶液5ml` | 用药「氨溴特罗口服溶液」· 5ml |
| `吃美林5ml bid` | 用药「美林」· 5ml · bid |
| `吃药后咳嗽` | 症状「吃药后咳嗽」（**判不准时按症状处理，不猜**） |

> 语音输入：应用里不做语音按钮（浏览器语音识别在 Chrome 走 Google 服务、国内不可用，
> 微信内置浏览器也不支持）。**用手机输入法键盘上的麦克风**说「5点半 37.5度」，
> 文字进输入框后上面这套解析自动生效，效果一样。

### 15. 症状「记一笔」与编辑

- **记一笔**：点已有症状上的「记一笔」，名称自动带过来，你只要选状态（存在/好转/已消失/不确定）
  和可选的数值 —— 保存后时间轴按时间排出「存在 → 好转」的变化，不用重打症状名。
- **编辑**：名称、出现时间、状态、数值、程度、部位都能改，不用删了重录。
- **出现时间**默认显示当前时间的一行文字，**点一下才展开**选择器。
- 报告列表会给每份报告标出「**已入病程**」/「**未入病程**」，免得漏挂。

### 16. 点一下就能记（症状与药都变成按钮）

日常最高频的动作不是"新建一条症状"，而是"**再记一次**"（咳嗽加重了、又喂了一次药）。
所以「快速记录」里直接把**本次病程已有的症状**和**医生开的药**列成按钮：

```
快速记录
症状 · 点一下记一次
  [咳嗽] [鼻塞] [发热] [流鼻涕(虚线)] [补充症状 +]
医生开的药 · 点一下记服药量
  [氨溴特罗口服溶液] [复方氨酚甲麻口服液]
  [补充用药 +]
一句话记（回车直接记入）
  [ 例如 5点半 37.5 ／ 三点五十吃氨溴特罗口服溶液5ml ]
```

- 点症状 → 弹小面板：**时间（已是现在）+ 状态**；发热/体温这类多一格「数值」。
- 点药名 → 弹小面板：**时间 + 这次吃了多少**（上次的用量自动带出来）。
- **虚线边框**的是"本次还没记过"的常用症状，点一下就开始记。
- 「补充症状 / 补充用药」是"记一个全新的东西"用的，字段更全。
- 面板里可以「**保存并再记一条**」——发烧一天要量好几次，不用反复开关。
- 记完留一行可点的提示（「已记入服药「…」」），点「修改」直接打开面板：
  **直接入库也有地方改**。

> 时间轴条目上原来的「记一笔」按钮已取消：记录入口统一收到「快速记录」里，
> 时间轴上点「编辑」则是改已有的那一条。

### 17. 服药记录（今天吃了几次、每次多少）

医生开的药是"**医嘱**"，服药记录是"**流水**"，两者分开：

| | 医生开的药 / 自己补录的药 | **服药记录** |
| --- | --- | --- |
| 回答的问题 | 这次在吃哪些药 | 今天几点吃了、每次多少 |
| 数据表 | `report_medications` / `case_medications` | `case_medication_intakes`（未编号草案） |
| 时间轴标记 | 「用药」（蓝色） | 「**服药**」（蓝色） |

同一种药一天可以记很多条，不去重 —— 这正是"这一天吃了几次退烧药"的答案，
也会写进「给医生看」的摘要和痊愈小结。

### 18. 症状状态按时间跟踪 + 体温按高低标色

- 状态四个：**存在 / 加重 / 减轻 / 消失**（旧数据的「不确定」在编辑时仍可见）。
  同一症状连着记，时间轴就排成一条变化线，并显示「**距上次 N 小时**」。
- 体温这类带数值的症状，时间轴上直接显示数值并按高低上色：

| 体温 | 颜色 | 含义 |
| --- | --- | --- |
| < 37.5℃ | 绿 | 正常 |
| 37.5 – 38.4℃ | 橙 | 低热 |
| ≥ 38.5℃ | 红 | 发热（常见"要不要吃退烧药"的门槛） |

## 二、顺手修掉的问题（含官方原版遗留）

| 问题 | 现象 | 现状 |
| --- | --- | --- |
| 疾病目录空 | 门诊/住院的诊断写在报告的「临床诊断」字段，原先只在诊断表里找，结果目录是空的 | 两个来源合并统计，已修 |

| 切回页面不刷新 | 页面被缓存，加完病程回来看不到变化 | 重新激活时自动刷新，已修 |
| 日期面板被裁 | 靠近窗口底部时，日期选择框被窗口下缘切掉、显示不全 | 下方放不下就向上翻转，已修（官方遗留问题） |
| 移动端没有返回按钮 | 手机上进「疾病」「病程」后出不去 | 已补返回入口（官方遗留问题） |

| 一句话记把时段词当症状名 | 输入「昨天下午体温3点 38.2度」，名称被解析成「下午体温」 | 时段词不再落进名称，且与钟点之间夹了字也能认出，已修 |
| 时间显示成「请选择」 | 已有时间的症状，编辑时时间栏显示成空 | 兼容两种时间格式，已修 |
| 手机按钮被挤走 | 时间轴头部按钮文案太长，手机上把「添加症状」挤出屏幕 | 排序/摘要/补录改为图标按钮，已修 |
| 中文数字时间不认 | 输入「三点五十吃氨溴特罗口服溶液5ml」，时间和服药动词被当成药名 | 支持三点五十/十点半/两点二十/十二点，已修 |
| 「十二点」算成 0 点 | 没写时段词时按"离现在更近"补 12 小时，12 点会滚到第二天 | 改为 12 点直接用 12:00，已修 |

## 三、怎么更新到 NAS

部署包在 `健康档案部署/二开版/`，用的是 **overlay 免构建更新**：
只替换程序文件，不动数据库、不用重新编译镜像。

```bash
# 把 overlay.tar.gz 和 更新.sh 传到 NAS 的 /vol1/1000/docker/health-records/
sh 更新.sh
```

脚本会先停容器、清掉旧程序文件、再整套解压，避免新旧文件混在一起导致报错。

> **NAS 上的重要目录**（建议纳入备份）：
> `/vol1/@appdata/fnos-app-health-records/data/` —— 数据库和上传的报告原件都在这里。

### 两条使用上的注意事项（不是 bug）

1. **用药能不能识别出来**，主要取决于报告的 **OCR 文字质量**。上游 v0.2.11 起已经扩展了
   处方、门诊与出院带药识别，**概览模式也会抽用药**（多栏、跨页用药清单也支持），
   所以不必再为了用药去把解析程度调成「详细」。识别不到时，先去看这份报告的 OCR 原文里有没有药名。
2. **病因只能手工填**，这是刻意设计的——医疗信息上宁可空着，也不让 AI 去推测。
3. **「一句话记录」是纯规则解析**，判不准时一律按症状处理（例如「吃药后咳嗽」），
   不会去猜你的意思；而且**回车就直接入库**，识别不准时用提示条的「修改」改一下。
4. **就诊卡片上的「缺剂量」「没抽到用药」只是提醒**，是让你去核对原报告，不是系统报错。
5. **报告带出来的药不能单独编辑**（它是报告原文的展开），要改得改报告本身；
   想记"实际吃了多少"，用「快速记录」里的药名按钮记一条**服药记录**。
