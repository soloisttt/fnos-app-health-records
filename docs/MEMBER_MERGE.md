# 成员档案合并

入口：我的 → 维护工具 → 成员档案合并，仅管理员使用。按成员档案选择迁入与保留方向，不合并登录账号，不按姓名自动判断身份。摘要列表只含姓名、档案编号、创建账号、本人账号、报告数量及创建时间，不含报告标题、结果或原件链接。

## 信息与授权

核对基本信息时逐项选择来源或目标值。默认保留目标授权，来源独有账号须明确勾选；最终获授权账号可访问双方全部数据，未保留账号失去访问权。至少保留一名有效且有共享管理能力的管理者。可明确选择保留一个现有本人账号，或暂不关联；默认优先保留目标的有效本人账号。保留的本人账号必须有最终访问权。其余账号仅解除本人关联，不删除账号或健康数据，是否继续访问由最终授权决定。不可用或待恢复的备份身份不能选为本人，不按同名自动绑定。预览列出保留及解除的关联，并由管理员确认。当前管理员不会自动获授权，报告接口仍按原有成员权限执行。

本人和默认选择同步处理：选定本人账号关联目标，其余双方本人关联清空；有目标访问权的默认选择指向目标，无权限则清空。个人隐藏和趋势收藏冲突时保留目标值。保留目标创建者、头像和家庭关系；姓名、生日、性别和血型按确认选择，血型报告来源标记清除以避免错误归因。

## 数据处理及恢复边界

完整备份成功后才执行数据库事务。保留报告 ID、文件路径、OCR/AI 结果、附件、补充记录及人工校对；迁移报告（含回收站）、提醒、通知、收藏、判重记录、文件清理关联和上传回执的成员归属。历史库保留的 `health_events`、`health_episodes` 按存在情况迁移；先更新阶段和事件归属，再迁移报告，保留资源关联、事件关联及原有触发器，不给新库额外创建旧版业务表。原件不搬移，不重新 OCR/AI，不自动去重；需要时使用重复报告检测。形态自动关联重建，人工关联保留。

来源成员标记已合并并退出普通列表，原授权移除；成员合并记录保留来源、目标、操作人、数量、备份引用及时间。报告旧链接按目标权限重新校验；旧成员链接不绕过授权。上传回执保留，成员变更后原上传请求键可能返回冲突，须使用新请求键，不自动重复上传。

执行不跨事件循环让出控制权，先拒绝其他活跃请求、存储迁移、恢复、导出、归一化和维护任务，以及所选档案未完成的识别/补页任务。备份后在 SQLite 写事务中复核预览指纹，完成后核对报告数量及外键。异常整体回滚；进程中断由 SQLite 回滚未提交事务。已完成请求通过持久记录幂等返回，服务重启后也不会重复合并；未执行预览在重启后作废。

成功后不提供一键拆分。误合并需使用完整备份恢复；这是全应用恢复，不是仅恢复两个成员，合并后的其他修改可能丢失，恢复前应再次备份和预检。合并备份可在现有备份列表找到。

## 本地接口

全部使用现有登录、CSRF 和维护中间件，并返回 no-store；服务层独立检查管理员及账号状态。

| 接口 | 用途 |
| --- | --- |
| GET /api/maintenance/member-merges/candidates | 分页成员摘要，q、page，每页 20 条 |
| GET /api/maintenance/member-merges/selection | sourceId、targetId，加载基本信息及双方现有授权 |
| POST /api/maintenance/member-merges/preview | sourceId、targetId、choices、grants、selfUserId（账号 ID 或 null）；生成绑定操作者及内容的 10 分钟凭证 |
| POST /api/maintenance/member-merges | token，执行已确认方案；重复请求幂等 |
| GET /api/maintenance/member-merges/:id | 当前操作者的完成记录 |

预览不包含报告内容；指纹只在服务端内存保存。预览后成员、报告、授权或相关归属变化需重新预览。账号不可用、身份待恢复、重复/非法授权、无管理者及未明确处理的本人归属冲突均阻止执行。存在未登记的成员关联结构时拒绝合并，不猜测迁移方式。

## 数据库与验证

新增 member-merge-draft.ts 和 member_merges 表。新库、旧库及备份恢复均通过现有初始化补齐；旧库缺表时先备份。保持当前应用版本及 schema 编号，正式迁移在获得发布授权后统一登记，已发布迁移不变。

自动化验证覆盖权限隔离、摘要隐私、本人/授权冲突、陈旧和过期预览、跨管理员凭证、重复执行及重启、事务故障、备份失败、收藏冲突和回收站保留、旧库补齐及界面二次确认。真实 fnOS/Docker 的大档案备份耗时、磁盘不足及中断恢复仍需在测试数据上验收，不用真实健康数据做破坏性测试。
