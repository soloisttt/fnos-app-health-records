# 反馈服务接入

应用浏览器访问本地 `api/feedback/...`，由应用后端转发至 `https://health.lby.link/api/v1/health/feedback`。服务地址固定为 HTTPS，禁止跟随重定向，不转发本地 Cookie 或网关账号，转发时始终使用服务端保存的安装身份。所有本地反馈接口要求已登录，沿用现有 CSRF、维护模式及 fnOS / Docker 鉴权。

浏览器进入反馈页面时先请求本地 `GET api/feedback/identity` 获取当前安装标识，再携带 `x-client-id` 查询列表；后续列表、详情、截图上传及写入请求统一带此头，开发与生产一致。标识仅用于反馈请求，不保存到浏览器持久存储，初始化接口要求登录并禁止缓存，不访问远程服务。首次使用由后端生成并保存安装身份（内部配置键 `x-client-id`），通过 `x-client-id` 发送。应用启动、普通页面和诊断预览不触发远程登记。同一安装的本地用户共享反馈记录，界面明确提示。身份备份恢复规则见 [备份恢复](BACKUP_RESTORE.md#反馈安装身份)。健康档案应用本地无表结构变更，不增加 schema 编号。

统一反馈服务在 `health_installations` 中同时保存完整 `client_id` 与 SHA-256 摘要 `client_hash`，仍按哈希唯一关联反馈。首次有效访问反馈列表、上传或提交时登记，不在应用启动时上报。管理端列表展示哈希摘要；具有安装设备查看权限的管理员可在“查看环境”中查看完整标识。完整标识不放入反馈环境快照、日志或公开诊断，也不随普通反馈列表/详情返回。本地登录后的身份接口和管理端安装详情接口是授权读取完整标识的入口，均禁止缓存。

支持列表分页与搜索、详情和处理记录分页、截图上传、提交、补充说明、确认解决和重新打开。列表及详情展示修复版本。POST 使用独立幂等键，当前页面内相同请求失败重试复用键；成功后清除。未提交草稿保留在当前页面内存，刷新会丢失。截图编辑只上传编辑后的文件，最大 6 张、每张 10 MiB；上传临时文件使用受限权限并清理。远程错误不显示假成功，不暴露上游响应或凭据。

提交前展示版本、部署、系统、OCR、AI 开关与浏览器环境。按白名单组织结构化字段，不发送原始 UA、构建标识、账号、密钥、报告或检查结果。描述和截图由用户主动提供，提交前提示遮挡隐私信息。

验证包括内存/文件 SQLite 身份持久化、完整备份恢复、H3 本地路由和模拟远程服务、Vue 交互测试。不自动向生产服务提交测试反馈。部署需使 `/api/v1/health/feedback/tickets` 可达；无身份请求应返回 401，404 表示需检查路由部署及代理。fnOS 与 Docker 上需继续验证真实网关访问、图片上传和备份恢复。
